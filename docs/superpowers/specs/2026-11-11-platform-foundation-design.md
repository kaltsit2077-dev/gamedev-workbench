# 本地优先的 AI 游戏开发工作台：长期设计与本轮范围

日期：2026-11-11。依据：用户明确要求依次实施架构可靠性、创作链、跨引擎执行与实际收益验证，并授权连续执行和自行验证。以下技术选择由本轮实施者提出，不冒充用户逐项决定。

## 产品形态

长期产品是本地优先、可扩展的 AI 辅助游戏开发平台。知识库、技能和工具是平台的可独立使用组件，共享任务与证据契约。保留独立技能安装和无账号离线工具；当前 AI 执行者是宿主代理，不声称已经提供独立聊天服务或模型调度后台。

典型旅程：意图与项目约束 → 可编辑设计包 → 引擎适配执行 → 原生项目产物 → 检查和画面 → 人的反馈与下一次迭代。状态分 draft / ready / passed / failed / blocked / not-run；文件存在和结构检查通过不等于游戏体验验收通过。

## 本轮四条交付

1. 架构可靠性：从引擎官方开源示例固定少量外部源码，保留 MIT 许可、提交、路径和 hash。先独立梳理标签并冻结，再运行现有分析器；记录初次结果、误报/漏报与未知，不为漂亮分数反复改标签。标签由本助手核对，不称为独立人类盲评；一旦观察结果并用于修复，该集合即变为回归集。未能完成图解析时仍保留动态不确定性。
2. 创作工作区：create-workspace 从明确 brief 创建新的、自包含的可编辑设计包，串联体验、机制、叙事、风格、UI、资产、实现与验收。check-workspace 检查引用、任务 DAG、产物存在及有限叙事/经济/资产模型；不声称自动绘画、建模或完成引擎集成。无远程请求，无覆盖。
3. 适配执行：提供版本化能力声明和共同执行报告。Godot 复用原始样例，Unity/Unreal 复用各自编辑器案例；无编辑器为 blocked。提供项目声明的测试计划预览与显式运行入口，结构化 argv、超时、退出码、严格的结构化检查、来源 hash。只运行被明确选中的入口，不扫描后自动执行；进程与引擎仍有其正常用户权限，副作用由项目声明。
4. 收益验证：建立架构/菜单/效果三个可复现验收任务和缺陷检测对照；冻结目标与判据，计时只算明确的工具步骤。原始工件与工具诊断可实测；同模型独立上下文产出、人工架构盲评和账单不存在时必须保持待采集，不能将脚本检出率或自评当生产力增益。保留既有负向模型试验。

## 核心边界

- Python 3.11+ 标准库，核心继续随技能自包含分发；本轮不搬动既有目录。
- 公开仓库与私有游戏分离。真实私有游戏的源码与根 .godot 缓存只读；本机引擎不能写受保护目录时，可在确认忽略的独立临时目录运行原创案例副本。私有源码/报告不进入公开发行包。
- 创建工作区与报告独占写入，路径需留在所选根内、拒绝符号链接；有界输入与 JSON 严格字段校验。
- 用户项目运行默认预览；显式 --execute 后才启动被声明的命令。stdout/退出码本身不足以背书行为；只有有效检查证据可判 passed。
- 统一报告同时保留原生结果、引擎版本、检查范围和未测维度；不以一种引擎的通过替代另一种。
- 无云上传、隐式软件安装、账单估算或模型调用。MCP 等适配必须先有具体编辑器操作缺口。

## 反目标与防退化

不以条目数、支持引擎图标数或检查数量代替可用性；不把所有资料一次塞进模型上下文。先选择任务需要的知识，再引用来源。平台状态必须能指出对应项目快照，陈旧截图不显示为当前通过。美术输出必须可编辑、标注来源/许可与实际制作状态。人工体验判断仍有明确入口。

## 本轮验收

外部样例标签冻结与可重跑结果；工作区创建/破坏输入/任务循环/越根检查；共同报告对缺失/空检查/失败/超时的测试；官方 Godot 在副本真实执行、其他编辑器缺失真实 blocked；三个任务的原始失败与工具诊断记录；公开说明尚无新增生产力/费用结论。更新使用文档、运行相关回归、包检查、CI 后发布预览版。
