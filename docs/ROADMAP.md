# 后续完善路线

先把最常用任务做深，以真实请求与验收结果决定投入。这里是候选方向，不代表已实现或承诺日期。

| 顺序 | 具体工作 | 完成的判据 |
|---|---|---|
| 近期 | 将 UI/效果助手接入一个原创真实菜单与较复杂效果 | 多尺寸、长文本、返回/焦点恢复、重复打开关闭；物理输入与画面单独记录 |
| 近期 | 架构分析的 UID 与动态引用支持 | 有限解析范围明确，人工核对误报/漏报，保持只读且不编造状态所有权 |
| 近期 | 扩展固定配对任务，测新增工具的收益 | 预先冻结完整验收、重复/轮换顺序、匿名盲评、保留失败；实际费用不可得时继续留空 |
| 近期 | 项目声明的测试入口与证据适配 | 可预览明确命令，超时/失败真实可见，用户场景副作用与隔离由配置说明 |
| 后续 | 一个编辑器 MCP 的实用对比 | 出现 CLI 无法解决的操作后，在同任务完成读/改/撤回/运行/停止与权限核对 |
| 后续 | Unity、Unreal 的原创运行案例 | 在各自环境运行并保存版本、产物、行为和画面证据 |
| 后续 | 叙事分支检查、数值/经济模拟、音频事件与灰盒关卡 | 每项都有原创输入、可执行产物、失败案例与实际验收 |
| 持续 | 外部来源更新与社区反馈 | 新条目说明具体任务和来源，明确许可/依赖/费用，不因条目多就声称全面可用 |

更全面的地图已经存在；当前主要短板是代表性案例、跨引擎执行和独立用户验证。扩大功能应能解决具体制作问题。发布后通过仓库 Issues 收集复现与真实任务，优先处理可验证的阻碍。
