## 设计与限制

- 原创小型 Godot 工程，真实 Git 公共基线与两个分支分别增加设置，合并产生真实索引冲突。它不是现有私有游戏，也不代表中型项目的规模。
- 派发前冻结全部输入、13 项原生 grader 和 Python 驱动的 hash；先验证阴性对照。早期夹具的原生类重名解析问题和版本字符串格式差异在派发前修正，未用实验输出调验收。
- 两组新上下文、相同继承模型配置和工具、无模型覆盖；精确后端 ID 不可得。A 先于 B 派发，两组并行，父任务也在同宿主工作；无先验根因、修复方案或 grader 提供给代理。
- 墙钟从共同准备完成到父任务观察到完成，包含派发/观察延迟、阅读、工具、自测、文档与主机竞争；不是模型延迟或精确独立任务计时，不作显著性推断。
- Skill 是手动指定读取；没有测自动发现。保留完整派发快照，未偷偷替换为发行时版本。发布前修正描述字段 YAML 引号，并给 Git 工具增加子模块/延迟取物保护；未用这些后改动重算处理结果。流程正文没有改动。
- 各组自己的额外断言只在 NOTES 中作为代理执行记录保留，不作为共同评分加分。公共比较只用同一冻结验收。
- 没有真实输入、渲染、性能、完整游戏或长期多人团队验证。Godot 根证书读取诊断单独保留为已知环境限制；其他错误仍判失败。原始含主机路径日志留在本地，公开结果保留诊断数与原生检查。

## 复现工具与产物

完整项目含准备/验收脚本，不自动调用模型：

```text
python tools/engineering_eval.py prepare --output "新的隔离任务目录"
python tools/engineering_eval.py grade --case "该目录/arm-a" --engine "官方Godot可执行文件" --output "新的A验收目录"
python tools/engineering_eval.py grade --case "该目录/arm-b" --engine "同一官方Godot可执行文件" --output "新的B验收目录"
```

prepare 创建 seed 和相同起点的 arm-a/arm-b，包含真实未解决合并。分别把 REQUIREMENTS.md 与项目提供给两个独立助手，仅 B 提供固定技能；隐藏另一组和 grader，先完成再验收。使用引擎可写的独立目录，不与正式项目或开着的编辑器共写缓存；原生验收专为本案例使用官方 4.7.2。

公开 outputs 只含两份改动脚本、说明和共同结果，不包含 .git。若要重验归档产物，先 prepare 新副本，再将相应 outputs 的两个脚本覆盖到对应副本，暂存 settings_state.gd，最后 grade。CI 只验证准备/冻结与归档完整性，不冒充原生引擎执行。
