# 第一轮配对评估：尚未证明技能提效

日期：2026-11-11。任务为原创 Godot 充能反馈功能修复，涉及模型边界、同步通知、原生 UI 接线、重复触发与继承暂停。真实运行并完成代码修改，但仍只是独立小项目预试验，不能代表完整商业游戏开发。

## 条件与流程

- 两组从相同的原始任务文本和文件开始，均在独立新上下文中完成，不能读取另一组产物。
- 相同继承的父级模型配置，没有模型覆盖；宿主没有提供可记录的精确后端模型 ID，不能据此声称跨后端完全可复现。
- A 不读取自定义技能；B 读取 gamedev-workbench 0.2.0-preview。两组仍共享宿主规则和技能目录元数据，未彻底消除共同先验。
- 两组接收同样的环境补充；A 此前已有环境失败重试，B 在首次引擎运行前得到补充，耗时存在环境干扰。
- 行为要求在运行前固定，具体共同 grader 在两组结束后实现，未读修改源码来挑选断言；并非预先盲藏完整测试代码的严格实验。
- 共同验收在临时副本执行，代理自测数量不作通过率指标。使用相同 Godot 官方基准。

## 结果

| 计量 | A：无自定义技能 | B：有技能 |
|---|---|---|
| 共同验收 | 15/15，通过 | 15/15，通过 |
| 共同验收后的返工 | 0 | 0 |
| 代理记录工作耗时 | 261.846 秒 | 343.781 秒 |
| 自测行为调用 | 3 轮，含环境重试 | 2 轮，包含修复前红灯与修复后绿灯 |
| token / 实际费用 | 未暴露，null | 未暴露，null |

耗时来自各组首次至最后工作记录，不含最终答复生成；包含阅读、工具等待和环境处理，不是纯模型推理延迟。B 本轮更慢，但不能从单个受干扰任务归因出普遍的效率变化。

两组都修改既有三个生产脚本，并提供审查与结果文档。B 文档显式列出状态所有权和边界方案；A 也指出相同主要问题。这里没有独立人类盲评，不为文档质量虚构评分。

阴性对照：相同 grader 对未修复版本两份输入均只通过 7/15，判失败；说明验收不是无条件报成功。最终脱敏产物再次验收均通过。

## 可以得出的结论

流程可在没有额外模型 API 账号的情况下组织独立任务、保留产物并统一验收；本例两组都能完成修复。尚未观察到通过率或返工改善，不能宣传“显著提效”。本轮也没有评估新增 0.3 分析/图形工具对代理表现的影响。

下一步应冻结更多架构/UI/效果任务及完整验收代码，覆盖不同复杂度；轮换执行顺序，重复运行并加入独立盲评。费用比较需宿主提供实际使用计量或用户自有 API 记录，不能从文件字数或墙钟推算。

原始任务与复验方式见 [评估夹具](../evals/paired/README.md)，机器结果见 [共同验收](paired-results.json) 与 [阴性对照](paired-negative-results.json)。这些是本次快照，不是持续保证。
