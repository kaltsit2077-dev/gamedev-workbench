## 原创案例：编译正常，架构契约失败

状态类 `domain/run_state.gd` 误继承了界面类 `presentation/widget_state.gd`。金币值能变化、界面适配类能读到新值，编译也正常；但状态对象因此暴露了界面方法，违反案例明确声明的模块契约。

修复仅把状态类父类改为 `RefCounted`。界面仍通过注入读取同一个状态，不改金币逻辑、显示适配代码或验收脚本。

| 同一验收 | 修复前 | 修复后 |
|---|---|---|
| 原生编译 | 通过 | 通过 |
| 初始状态、注入后读取、变更后读取 | 3/3 | 3/3 |
| 状态不暴露界面 API | 失败 | 通过 |
| 原生行为合计 | 3/4 | 4/4 |
| 新模块检查 | 指出 1 条 `extends-class` 违规 | 无该违规 |

本次还实际运行了 0.9 发行工具：它在修复前报告没有观察到违规，漏掉了该命名继承。[原始报告](architecture-case-v010.json) 保留旧工具指纹、原生检查、退出码、静态证据和诊断计数。

案例是预设缺陷的原创演示，不是用户游戏里的生产故障；这里证明检查覆盖和修复保持相关行为，不能证明模型更快、更省钱。官方 Godot 4.7.2 / Windows headless 实跑，不含渲染、实体输入或性能结论。

完整项目中复现：

```text
python tools/run_architecture_case.py --engine "官方Godot可执行文件" --scratch "新的引擎可写副本目录" --output-dir "新的引擎可写证据目录"
```

两个目录须全新、彼此独立并位于技能源码之外。运行器复制包内 before/after 工程，保持原件不变；副本会产生引擎缓存/UID。before 预期失败一项，因此总报告中的 matched_expected_result 表示重现符合预期，不表示修复前游戏通过。可选 `--baseline-skill "解压后的0.9技能根"` 会执行显式选中的旧版 Python 工具进行对照；它不自动下载。
