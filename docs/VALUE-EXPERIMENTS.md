# 工具缺陷检出与生产力评估

[本轮原始记录](tool-value-v07.json)比较的是同一原创案例上的“只做引擎解析”和“运行专项工具”。三个缺陷及源 hash 在第一次执行前冻结于 [协议](../evals/tool-value/protocol.json)，每项都执行正常副本和单缺陷副本。

| 任务 | 预设缺陷 | 仅解析 | 专项工具 |
|---|---|---|---|
| 架构线索 | 运行时 load 指向不存在的资源 | 未检出 | 输出 missing.tres 引用 |
| 菜单 | 返回时遗漏恢复原控件焦点 | 未检出 | 报告返回/取消焦点断言失败 |
| 效果 | elapsed 被钳到 duration，却用严格大于判结束 | 未检出 | 报告效果结束后仍未隐藏/空闲 |

三个正常副本全部被两种检查接受。三个预设缺陷仅解析均未检出，专项工具均检出。原始记录包含各阶段墙钟：架构扫描约毫秒级；菜单/效果的行为运行比单纯解析耗时更多。该结果说明增加检查可以发现这三个已知缺陷，**不是同模型开发实验，也不证明总开发时间、返工或费用下降**。

复现，需要官方 Godot 4.7.2 和引擎可写 scratch/output：

```text
python tools/evaluate_tool_value.py --engine "Godot官方路径" --scratch "引擎可写缓存" --output "新的实验目录"
```

工具不改冻结案例；在临时副本注入缺陷。菜单/效果执行 headless，不产生新的渲染或物理输入证据。任务与验收由本项目作者设计，不能推广为所有游戏缺陷的检出率。

## 下一轮真正的生产力试验

分别选择真实架构审查、原生菜单修改、效果实现任务，各自准备相同项目快照、完整需求与事先冻结的验收；A 不使用本工具，B 使用明确版本的分析/任务包/验证工具。运行上下文独立，模型与工具权限相同，避免看见对方结果或隐藏验收。交替顺序并记录环境、人工干预和总墙钟。

质量：行为/画面验收 + 匿名的人类架构/交互评审；返工：共同验收后修正轮数；时间：包含准备和验证的全流程；费用：供应商实际导出与可追溯公开记录标识。估算与缺失保持分开，不由墙钟推算 token。

本轮这些新增独立模型任务尚未派发，人工盲评和账单未取得；`new_model_trials.status=not-run`，费用/token 为 null。现有工具可以汇总真实记录，不能制造这些数据。既有 0.2/0.4 小样本模型试验仍未证明提效，见 [原方法与结果](PAIRED-EVALUATION.md)。

## 产品投入的判断

保留能定位真实缺陷、产物可编辑且可以重复验收的能力；每增加一个适配器，先说明实际操作缺口、环境和验证成本。下一轮优先把检查接入真实项目，再评估任务完成质量与总成本；失败和无收益同样公开保留。
