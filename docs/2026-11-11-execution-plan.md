# 执行型工具与对照评估计划

本轮执行用户明确选择的路线。目标：同配置代理对照、只读工程线索、可复现 UI/效果验证；先验证 CLI 能力缺口，不自动接 MCP 或公开发布。

## 架构与接口

- `scripts/project_analysis.py`：`analyze_project(path)` 返回 Godot 配置入口、autoload、资源引用边、动态引用限制、GDScript 状态赋值线索；仅读文本，排除缓存/隐藏目录、测试、插件和符号链接，提供范围选项，不证明完整调用图或唯一所有权。
- `scripts/quality_checks.py`：`check_sample(engine, output_dir, scratch, graphical)` 在样例副本中运行焦点、生命周期、多尺寸几何检查；可选真实渲染导出连续帧。只验证自有样例，不执行任意用户项目。
- CLI `analyze-project` 和 `check-ui-effects` 连接上述接口，保持 JSON、明确失败退出码与证据维度。
- 原创独立缺陷样例：两份相同输入由独立新上下文执行，只有一组读取本技能；根侧冻结验收后再检查产物。不将解题过程泄漏给另一组。

## 任务与验收

1. 冻结缺陷样例、任务与评分规则；准备 A/B 副本，保留文件 hash 和独立工作记录。同一继承模型配置，无模型覆盖。费用和 token 不可取得则 null。
2. 只读分析先测：注释/字符串中的假引用、相对路径、循环、动态路径、符号链接、隐藏/缓存排除、读取前后 hash。
3. UI/效果先测：窄屏/宽屏布局、程序化焦点导航、实际按键事件、固定时刻画面、重播复位、暂停时钟、结束隐藏/清理。headless 与真实渲染分列。
4. 将工具应用于当前项目只读，并保留私有结果在发布包外；生成可公开的原创样例结果。
5. 汇总两组实际验收、文件改动、耗时、返工证据和缺失计量；一个配对任务不是统计性提效证明。
6. 更新技能、支持矩阵和预览包，复测便携性。MCP 仅在这些任务确有无法覆盖的编辑器操作时再做同任务比较。

## 风险与限制

静态线索不是语义编译器，不把属性名相同认定为同一状态；不扫描私有凭据或上传工程。代理对照共享宿主基础规则和技能元数据，无法声称完全无共同先验；保存这一限制。真实画面必须有实际图形后端，无法运行时不伪造。
