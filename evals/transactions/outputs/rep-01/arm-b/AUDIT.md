# 设置事务审计

## 问题与变化压力

任务仅涉及 `Settings` 的同步设置事务，依据 `REQUIREMENTS.md` 保留构造函数、`values` 属性和 `apply(changes)` 接口。无需游戏引擎、输入系统或全局通知设施。

## 现状入口与证据

原 `Settings.values` 返回内部字典；原 `Settings.apply` 直接 `update` 已拥有状态后调用持久化与通知。由此存在：

- 无输入校验，非法字段、音量或绑定均可进入状态。
- 绑定补丁替换整个绑定字典，丢失未修改动作，未检查最终绑定重复。
- 忽略持久化返回值，持久化异常也已提前修改状态。
- 对外暴露同一字典，调用方和两个回调均可改写内部状态。
- 无重入保护，回调可启动嵌套事务；异常直接外传。
- 有效无变化请求仍触发持久化与通知。

修复前执行本次新增测试：13 个测试方法，48 个失败、8 个错误（含参数化子测试）；测试进程退出码 1。原始证据为 `.run/baseline.log`。

## 模块 / 依赖方向

`调用方 → Settings.apply → writer(独立完整快照) → 内存提交 → listener(另一独立完整快照)`。

只使用标准库的 `copy.deepcopy` 与 `math.isfinite`。持久化具体实现仍由已注入的 writer 负责；生产代码不写文件、不使用总线或调度器。

## 状态 / 声明 / 唯一写者 / 读者 / 生命周期

| 状态 | 声明与唯一写者 | 读者 | 生命周期 |
| --- | --- | --- | --- |
| `_values` | `Settings.__init__` 初始化；`Settings.apply` 仅在 writer 精确返回 `True` 后替换 | `values` 只返回深拷贝 | Settings 实例 |
| 局部 `candidate` | 当前 `apply` 从已有状态深拷贝后合并合法补丁 | 比较、校验与回调副本的来源 | 一次 apply；成功后成为已提交状态 |
| `_applying` | Settings 在进入持久化前设置，`finally` 释放 | `apply` 入口 | 覆盖持久化、提交与通知 |
| 两个回调快照 | Settings 分别深拷贝产生 | 各自回调 | 由接收者持有；均不共享已提交状态 |

## 方案与取舍

1. 保留原地更新：无法可靠保证失败不改变状态，且回滚不能撤销已经发出的通知，拒绝。
2. 局部事务接缝：先完成全部校验与候选比较，持久化成功后一次替换，再通知；使用一个实例布尔保护和 `finally`。选用这一最小方案。
3. 新建存储层、事件总线、异步队列或通用事务框架：本任务没有跨对象协调要求，增加依赖与失败路径，且部分机制被需求明确禁止，不采用。

未来增加可修改设置需扩充字段校验、候选合并和行为断言；没有为未知需求建立框架。

## 接口契约与失败行为

- 仅接受非空字典，字段仅 `volume` / `bindings`。音量排除 bool、非数字、越界及非有限值；先检查范围，避免巨大整数转为浮点时溢出。
- 绑定为仅含 `jump` / `fire` 的非空字典补丁；值须为非空白字符串，按原字符串保存，不引入未要求的大小写或空白归一化。检查合并后两个动作的绑定是否重复，允许同一次补丁交换绑定。
- 有效无变化返回 `True`，两个回调均不执行。
- writer 仅精确返回单例 `True` 才提交；其余返回值和常规异常均返回 `False`，保持前次提交状态，不通知。不会对返回值求真假。
- writer 只收到候选完整快照的深拷贝，并在内存提交之前执行。listener 在提交后收到另一份深拷贝，只调用一次。
- listener 的常规异常被隔离；已经持久化并提交的请求仍返回 `True`。
- 持久化或通知期间的嵌套 apply（包括嵌套无变化请求）返回 `False`。两个回调的所有退出路径均经过 `finally` 释放保护。

## 迁移与回退

生产改动限定为 `settings.py`；测试和报告为新增文件，无数据格式迁移。回退可还原该文件，但会恢复上述已复现缺陷。没有更改需求、安装依赖、操作 Git 或访问其他试验目录。

## 验证与未测项

修复后相同 13 个测试全部通过，测试进程退出码 0，见 `.run/final-tests.log`。覆盖输入矩阵、合并与交换、完整快照、有效无变化、精确返回值、回调写入与事后写入隔离、提交顺序、失败后状态保留、两个回调的重入拒绝及异常后恢复。

这仅证明 Python 同步边界的行为。未运行游戏引擎、画面、性能基准或真实用户输入；未测试并发线程。回调捕获 `Exception`，不会吞掉 `KeyboardInterrupt` / `SystemExit` 等进程控制异常；`finally` 仍会释放重入保护。writer 在报告失败之前自身已经产生的外部副作用无法由本类撤销，外部持久化的原子性由 writer 保证。
