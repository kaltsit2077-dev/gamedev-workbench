# 设置事务审计

## 问题与变化压力

本任务只涉及独立 Python 夹具的同步设置事务。依据 `REQUIREMENTS.md`，必须保留 `Settings(writer, listener)`、`values` 和 `apply(changes)` 接口；不引入引擎、文件持久化实现或外部依赖。

## 现状入口与证据

原 `Settings.values` 直接返回 `_values`，调用方可绕过事务修改音量和嵌套绑定。原 `Settings.apply` 直接 `update` 已拥有状态，未验证输入、覆盖整个绑定映射、忽略写入结果，并把同一对象交给两个回调。没有重入防护，写入异常之前就已改变状态，通知异常直接向外传播。

修复前先运行新增行为测试：17 个测试方法，51 个失败断言、7 个错误，退出码 1。子测试使失败数可大于方法数；完整证据在 `.run/baseline-tests.txt`。

## 模块与依赖方向

`调用方 -> Settings.apply -> 注入 writer -> 提交 -> 注入 listener`。

`Settings.values` 提供读取快照；writer 和 listener 不获得内部对象。生产模块仅依赖标准库 `copy.deepcopy` 与 `math.isfinite`。

## 状态所有权

| 状态 | 声明与唯一写者 | 读者与有效期 |
| --- | --- | --- |
| `_values` | `Settings.__init__` 初始化；`apply` 成功持久化后的唯一提交点替换 | `Settings` 生命周期内有效；公开读取为深拷贝 |
| 局部 `candidate` | 本次 `apply` 验证并合并补丁 | 提交前为局部候选，失败即丢弃；成功后成为拥有状态 |
| writer/listener 参数 | 分别从候选状态深拷贝 | 各回调可保留或修改，不影响候选、彼此或提交状态 |
| `_applying` | `apply` 在持久化前设为真，在 `finally` 归零 | 覆盖 writer、提交、listener 的同步执行区间；拒绝嵌套调用 |

## 方案与取舍

保持原实现无法满足失败原子性。最小局部边界是验证候选、写入确认、单点提交、通知隔离和一个实例重入标记；采用此方案。另建事务服务、事件总线、调度器或引擎层会扩大接口和生命周期，没有本任务依据，未采用。

## 接口契约与失败行为

- 先拒绝重入，然后验证非空字典与允许字段。音量排除布尔值并检查范围和有限性；范围检查先于有限性检查，也可安全拒绝超大整数。
- 绑定只接受已知动作的非空字典补丁和非空白字符串；与当前绑定合并后拒绝重复值。字符串原样保留，不额外规范化大小写或空格。
- 验证通过且候选等于当前值时返回 `True`，不调用回调。
- writer 恰好收到一次完整候选快照，仅 `result is True` 成功；其他返回值和普通回调异常返回 `False`，内部状态保持原值，listener 不执行。
- 成功写入后才提交，再通知一次。listener 的普通异常不撤回提交，`apply` 仍返回 `True`。所有回调退出路径均经 `finally` 释放重入标记。
- 本类不执行文件写入，不提供线程同步、异步执行或外部存储的补偿回滚；这些不在给定同步接口要求内。

## 迁移与回退

仅替换 `settings.py` 的内部实现，保留构造参数和公开接口；新增 `test_settings.py`。无数据格式迁移或新增服务。若回退事务实现，应同步恢复原源码；本次测试会再次呈现原先缺陷，不能把测试调回错误行为作为修复。
