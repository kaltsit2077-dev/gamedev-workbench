# 原生游戏 UI

输入：页面任务、信息优先级、真实游戏状态、键盘/手柄/触摸范围、分辨率与风格参考。

1. 先画信息层级和导航流；列出默认、悬停、焦点、按下、禁用、加载、空、错误与成功状态中实际适用的项。
2. 明确输入所有权、模态栈、Esc/返回、暂停、焦点恢复与设备切换；提示从实际绑定读取。
3. 比较原生控件、自绘几何、位图、三维面板的成本。Figma/Penpot 用于设计稿；引擎实现分别使用 Control、UI Toolkit/uGUI、UMG/Slate 或目标 Web 框架。
4. 将字体/颜色/间距/尺寸与动效参数放在既有主题声明面。先确认字体许可、中文回退与长文本。
5. 接入实际数据和事件。容器布局与位移动画不能争写同一位置；装饰层不要拦输入。
6. 至少检查目标常用宽屏、窄屏和文字放大；按支持范围走完键盘/手柄路线。记录实际截图尺寸和操作结果。

交付：状态表、原生可操作界面、主题与绑定、截图和输入证据；使用 templates/ui.md。来源：S03、S04、T09、K06、K07。

验收：焦点可见且无陷阱，模态层截断底层输入，布局不溢出，低信息状态不伪造可用按钮。网页预览与静态截图分别标注，不代替游戏内运行。


## 可执行验证与复用

`check-ui-effects` 验证的是本技能自有样例，不自动测试用户界面。需要测试真实场景时，可将 `assets/godot-demo/validation_probe.gd` 复制到你授权的测试夹具：`control_bounds` 检查明确选中的控件，`focus_chain` 检查预期焦点集合，`send_action` 注入引擎动作。依照 `quality.gd` 的 resize/等待布局/截图流程接入你的场景；先明确哪些装饰或滚动内容允许越界。合成动作与几何断言不证明真实键盘/手柄和所有 DPI 环境。
