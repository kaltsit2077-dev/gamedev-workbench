# 有／无技能配对预试验

这里包含原创缺陷样例、固定要求、共同验收和两组脱敏产物。它是一个实际由代理修改并由 Godot 运行的独立小项目任务，不是来自商业生产任务的代表性样本集。

准备一致输入：

```text
python tools/paired_eval.py prepare --output "新的对照目录"
```

分别用两个全新上下文、同一模型与工具配置执行 arm-a / arm-b。共同要求位于各自 REQUIREMENTS.md；A 不读取自定义技能，B 读取本技能并按需加载。两组不要看到对方产物或 grader。记录第一次工作到最后工作之间的时间、工具运行轮次；不要猜测 token 或费用。此工具不自行调用模型，不需要 API key。

完成后用同一验收器检查：

```text
python tools/paired_eval.py grade --engine "Godot 4.7.2 官方版" --artifacts "对照目录" --output "新的验收目录" --scratch "引擎可写缓存"
```

grade 会在临时副本中加入共同验收脚本，保留代理原产物；任务未通过返回非零退出码。使用 outputs 作为 artifacts 可复验本轮已完成产物。每个任务仍需人工判断审查质量，不能拿自编断言数量比较优劣。

每轮另行记录模型、技能版本、隔离方式与环境干扰，可用 --metadata 指定 JSON。验收器不能自行证明这些条件；未提供则标为 unverified。复验本轮历史产物时可传入 evals/paired/run-metadata.json；不要将这份历史记录套在新的实验上。

输入 manifest 在 UTF-8 文本规范化 LF 后计算 hash；准备时给两组复制的是相同字节文件。验收的行为要求在代理运行前固定，具体 grader 脚本在两组结束后实现，未查看修改源码来挑选断言；这不同于提前冻结并盲藏完整测试代码，后续正式实验应进一步改善。

本轮 B 使用 0.2.0-preview；新增的 0.3 分析和图形工具不在该处理组内。结果、耗时与限制见 ../../docs/PAIRED-EVALUATION.md。原始日志留在用户本地评估目录，发布包只含原创样例、脱敏结果和产物。
