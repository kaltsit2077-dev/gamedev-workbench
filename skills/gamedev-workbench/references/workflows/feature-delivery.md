# 功能实现

输入：用户行为、具体触发、成功结果、失败路径、现有接入点与回归入口。

1. 将需求写成一个能观察的前后例子；确认运行时真正消费的数据，识别受影响契约。
2. 追踪现有通道，优先扩展既有装配和接口。列出新增状态及唯一写者，明确初始化、暂停、恢复、取消、重复调用和销毁。
3. 把复杂任务拆成最小可运行切片；实现数据、代码、场景接线与玩家反馈，逐项对应需求。
4. 按影响运行解析/编译、行为回归与真实场景检查；不能将模拟对象通过写成正式场景已验证。
5. 用实际 diff 核对完成声称，保留未验证项和复现方法。

交付：可运行实现、契约、必要数据与断言、变更说明、验证证据。使用 templates/delivery.md。

验收：入口真实可达；空数据/无目标/中断有明确行为；没有静默无消费者控件；退出后无事件或计时器残留。


多人协作先按 [Git 协作](git-collaboration.md) 核对改动归属、接口与共享文件。复杂交付用 [项目规划](project-planning.md) 保持切片依赖和可回退状态；不要只完成单个脚本而遗漏资源、装配或消费者。跨系统变更与存档/资源迁移，应在实际集成树上验证旧行为与新行为均可用。

对存档或长生命周期状态变化，分别检查保存事实、恢复引用/缓存和 UI 刷新；延迟效果、计时器与异步结果在退出/取消后应由原所有者撤销或拒收。使用项目已有状态机与取消机制，新增框架须有具体需求。参考 [上游方法](../upstream-patterns.md)。
